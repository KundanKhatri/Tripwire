# TripWire

**Theme:** Security in the Agentic Future
**Hackathon:** Microsoft Build AI 2026
**Team size:** 1 (solo)
**Live demo:** https://tripwire-arena.azurewebsites.net (provisioned during build — see [AZURE_SETUP.md](AZURE_SETUP.md))

> A real-time prompt-injection and exfiltration defense layer for agentic systems, built natively on Azure AI Foundry. Extends Azure AI Content Safety Prompt Shields with four additional defense layers Microsoft does not ship out of the box — capability provenance, canary tokens, behavioral anomaly detection, and a learning classifier — plus a live red-team arena where judges can attack a connected agent and watch TripWire block, classify, and explain each attempt with a reasoning trace.

---

## Why this matters

Every company shipping agentic AI in 2026 is one indirect prompt injection away from a breach. OWASP's LLM Top 10 lists prompt injection as the #1 risk. Microsoft has shipped Prompt Shields and Content Safety as a strong L1. But agents have **state, tools, memory, and goals** — and no commercial product today defends across all four. TripWire is that product.

## What it does

When you put TripWire between your user and your agent:

1. **L1 — Semantic Firewall**: Azure Prompt Shields + an embedding-similarity check against a curated attack corpus + pattern rules.
2. **L2 — Capability Provenance**: Every tool call the agent makes is signed with a trace token that proves which user input authorized it. Tools refuse calls without valid provenance.
3. **L3 — Canary Tokens**: Decoy "secrets" are sprinkled into the agent's context. If a canary ever leaves the agent boundary (in a response, a tool argument, or an outbound HTTP call), it is irrefutable proof of exfiltration. We block and alert.
4. **L4 — Behavioral Anomaly**: The agent's action trajectory is embedded and compared to the embedded user goal. Divergence = goal hijack. Triggered classifier vetoes.
5. **L5 — Learning Classifier**: A fine-tuned small model (distil-class) trained on the live attack corpus. Updates nightly from the arena. The product literally gets stronger as people attack it.

All layers are observable in real time via the **Glass Box** — a trace UI that shows which layers fired, why, and with what confidence, generated by GPT-4.1 on Azure OpenAI.

## The live arena (demo)

`/arena` lets anyone with the link try to jailbreak a connected agent. Attacks are scored, the leaderboard updates live via Azure SignalR, and successful attacks are fed back into L5 the next training cycle. This is the demo loop judges will see.

## Setup

See [AZURE_SETUP.md](AZURE_SETUP.md) for one-shot provisioning via `azd up`. Local dev:

```bash
# api
cd apps/api && python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload

# web
cd apps/web && pnpm install && pnpm dev
```

## Microsoft AI stack used

Per hackathon guidelines (mandatory):

- **Azure AI Foundry** — agent hosting, evaluation runs
- **Azure OpenAI Service** — `gpt-4.1` (explainer + agent brain), `o4-mini` (cheap classifier)
- **Azure AI Content Safety** — Prompt Shields for L1, Groundedness for L4
- **Azure Cosmos DB for PostgreSQL** — attack corpus + pgvector for embedding search
- **Azure Container Apps** — defense engine (FastAPI)
- **Azure Static Web Apps** — arena UI (Next.js)
- **Azure SignalR Service** — real-time arena leaderboard
- **GitHub Copilot** — disclosed AI coding assistant (see [AI_TOOLS_DISCLOSURE.md](AI_TOOLS_DISCLOSURE.md))
